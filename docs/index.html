Zscaler Split Tunnel for macOS

Route only the traffic you need through Zscaler. Everything else goes direct. Fast internet, full security where it matters.

Features

Everything you need for split tunneling

🔄

Automatic Route Management

Continuously removes Zscaler's broad routes that capture all internet traffic, keeping your connection fast.

🎯

Zscaler Route Configuration

Route specific domains, IPs, or CIDR ranges through Zscaler while the rest goes direct.

⚡

Automatic Config Reload

Configuration changes are applied immediately while the daemon runs on a low-frequency cadence.

🧠

Smart Zscaler Management

Starts Zscaler only when needed and manages its lifecycle intelligently.

🌐

Domain Resolution

Automatically resolves domains to IP addresses with caching for fast lookups.

👻

Daemon Mode

Runs silently in the background to maintain your split tunnel configuration.

🚀

Autostart Support

Optional launchd job keeps the daemon running after reboots. Set it and forget it.

Getting started

Quick Install

1

Make sure gh CLI is installed and authenticated with GitHub Enterprise.

2

Clone the repo, install the script, and start the daemon.

Terminal
# Set up Git access (if not already done)
brew install gh
gh auth setup-git
gh auth login -cwp https

# Clone and install
git clone https://github.com/balcsida/zscaler-split-tunnel.git && cd zscaler-split-tunnel

chmod +x zscaler-split-tunnel.sh && \
sudo mkdir -p /usr/local/bin && \
sudo cp zscaler-split-tunnel.sh /usr/local/bin/zscaler-split-tunnel && \
sudo chmod +x /usr/local/bin/zscaler-split-tunnel && \
zscaler-split-tunnel --add internal.company.com
sudo zscaler-split-tunnel --start
Usage

Commands

Basic Commands

# Start split tunneling
sudo zscaler-split-tunnel --start

# Stop the daemon
sudo zscaler-split-tunnel --stop

# Kill Zscaler completely
sudo zscaler-split-tunnel --kill

# Check status
zscaler-split-tunnel --status

# Show all routes
zscaler-split-tunnel --list

Configuration Management

# Add entries to route through Zscaler
zscaler-split-tunnel --add example.com
zscaler-split-tunnel --add 192.168.1.0/24
zscaler-split-tunnel --add 10.0.0.5

# Remove an entry
zscaler-split-tunnel --remove example.com

# Show current config
zscaler-split-tunnel --show-config

# Clear all Zscaler routes
zscaler-split-tunnel --clear-config

Advanced Options

# Custom check interval (seconds)
sudo zscaler-split-tunnel --start --interval 5

# Enable verbose logging
sudo zscaler-split-tunnel --start --verbose

# Run daemon directly (debugging)
sudo zscaler-split-tunnel --daemon --verbose

Autostart on Boot

# Enable autostart via launchd
sudo zscaler-split-tunnel --enable-autostart

# Disable autostart
sudo zscaler-split-tunnel --disable-autostart
Under the hood

How It Works

1

Broad Route Removal

Removes Zscaler's broad routes (like 1.0.0.0/8, 2.0.0.0/7) that capture most internet traffic.

2

Zscaler Routes

Adds specific routes for your configured domains and IPs through the Zscaler tunnel interface.

3

Continuous Monitoring

Runs as a daemon on a 5-minute interval to keep routes tidy without burning CPU.

4

Instant Reload

Signals the daemon to reload instantly whenever configuration files change.

Reference

Configuration

Defaults are versioned in the repository so the team shares the same baseline. User-specific overrides live in ~/.config/zscaler-split-tunnel/.

File Purpose
config/zscaler-split-tunnel.conf Default Zscaler routes forced through the tunnel
config/zscaler-bypass.conf Default direct overrides that skip Zscaler
~/.config/.../routes.conf User-specific Zscaler route overrides
~/.config/.../bypass.conf User-specific direct overrides

Files and Logs

Path Description
/tmp/zscaler-split-tunnel.log Runtime log file
/tmp/zscaler-split-tunnel.pid PID file for the daemon
/tmp/zscaler-domain-cache.txt Domain-to-IP resolution cache

Example Override File

# Routes to force through Zscaler
internal.company.com
vpn.company.com
192.168.100.0/24
10.0.0.50

Changes are written to disk immediately and the running daemon reloads the new configuration right away.

Help

Troubleshooting

Check if split tunneling is active

zscaler-split-tunnel --status

View detailed routes

zscaler-split-tunnel --list

Check the logs

tail -f /tmp/zscaler-split-tunnel.log

Verify a domain is routed through Zscaler

route get $(dig +short example.com | head -1)

If a site isn't loading

Run these commands to diagnose the issue:

# 1. Check DNS resolution
dig +short yourdomain.com

# 2. Verify the route
netstat -rn | grep <ip-address>

# 3. Test connectivity
curl -I https://yourdomain.com
